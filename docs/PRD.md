## 1. 一句话

Think My Day 是 Jonas 个人用的 macOS 菜单栏 App：从「开启一天」起，在本机完整记录电脑上发生的事；白天由 AI 安静地整理成一件件**事情**，并在发现新工作时询问是否加入**待办**；任何时候都可以打开复盘窗口，和 AI 对话，弄清楚今天做了什么、哪件事没做好。

## 2. 背景与问题

Jonas 是加密研究员，并行使用多个 AI Agent、浏览器研究、聊天工具和文档。一天结束时，他不清楚时间去了哪里、哪件事其实没做完或没好好做。只记「哪个 App 开了多久」回答不了「当时在做什么事情」；静态的报告又很难看进去，也没法当场补充和纠正。

v0.3 试图判断「跑偏」，但多次切换可能是同一项研究中的交叉查证，打开某个网站本身不说明偏离，「跑偏」这个标签对 Jonas 也没有用。他真正想知道的是：今天打算做的事做完了没有，没做完的卡在哪里。所以 v0.4 用**待办**表达意图，用**事情**还原实际发生的事，由 AI 在对话中把两者对照起来。

## 3. 目标与非目标

### 目标（v1）

1. 用户开启一天后，完整记录不看名单之外的所有 App：窗口文字、多窗口布局与焦点、网页地址等，形成可追溯的**记录**。
2. 白天增量整理：AI 定时把新增记录归纳为**事情**，复盘时打开即可对话，无需等待整天的处理。
3. 待办闭环：用户在开启一天时填写待办；AI 发现新工作时及时询问是否加入；只有用户本人能勾选完成；没做完的待办一直保留并显示已进行几天。
4. 对话式复盘：AI 依据待办勾选状态和记录里观察到的情况，以「观察 + 提问」指出哪件事没做好，用户确认后给总结性建议；用户可以追问、补充、纠正，可以跨天提问。
5. 全部数据在本机，库加密；写入前脱敏。
6. 模型可由用户自行配置，支持各家官方 API 与兼容接口。
7. 无需 Apple 开发者账号即可稳定安装，重装后授权尽量保留。

### 非目标（v1）

- 跑偏判定、打分、排名。
- 周期性全屏截图与录屏；击键监听；剪贴板监听。
- 跨设备同步、iCloud、账号体系；iPhone。
- Mac App Store 分发。
- 自带或自训练模型；内置订阅转接口的能力（交给 magpie 等外部工具）。
- 发送记录 / 外发审计界面。
- 日历等电脑之外的数据源；电脑之外的事情靠复盘对话里的用户补充。
- 解密 ChatGPT Mac 缓存；把 Claude Desktop / Muse 等当作有完整日志的一等数据源。

## 5. 用户旅程

### 5.1 首次启动（只出现一次）

1. **系统授权**：辅助功能（必须）、自动化 → Chrome（取网址）、屏幕录制（OCR 兜底用）、开机自动启动。缺少非必须授权时可以继续，相应能力标为不可用。
2. **计划开始时刻**：「你的一天一般从几点开始？」时区自动识别，可修改。
3. **配置模型**：选择官方 API 或填写兼容接口（见 §8.4），页面上提示可以用 magpie 接入订阅。可以跳过；跳过后只记录，不整理，也不能复盘。
4. **确认不看名单**：预先放入密码管理器、钱包和银行类 App，用户可以移出或添加。
5. 进入第一次「开启一天」。

### 5.2 开启一天

- 用户点菜单栏的「开启一天」，打开开启面板：
  - **待办**：列出所有没做完的待办及已进行天数，可以新增，也可以不填。
  - **不看名单**：沿用上一次的设置，可以修改。
  - 按钮「开启一天！」。
- 点了之后才开始记录。没有开启时不记录任何内容，也**不提醒**；用户打开菜单栏时显示「比计划晚了 X」。
- 开启后显示一次与计划开始时刻的对照，如「比计划晚 1 小时 30 分」「比计划早 20 分」，语气中性，不评价。

### 5.3 白天

- App 静默记录，不打扰用户。
- AI 每 15 分钟左右整理一次新增记录（§8.1）。
- 发现新工作时弹通知询问是否加入待办（§8.2），这是白天唯一的打断。
- 用户随时可以在菜单栏或复盘窗口里增删、勾选待办，修改不看名单。

### 5.4 结束一天

- 用户点「结束一天」，停止记录。
- 忘了点时，这个复盘日持续到下一次「开启一天」为止；中间睡觉等时段在记录里表现为无输入或睡眠。

### 5.5 复盘

- 任何时间都可以打开复盘窗口，不限于晚上，也可以复盘一天中途。
- AI 开场，用户对话，详见 §8.3。

### 5.6 回看历史

- 通过日期切换回看保留期内任意一个复盘日，也可以在对话里直接问「上周三我在做什么」。
- 在过往历史里可以删除某一天（§10）。

## 6. 采集方案

### 6.1 信号分层

| 层 | 信号 | 用途 | 说明 |
| --- | --- | --- | --- |
| 主 | 窗口可见文字 | 还原内容，支持归纳事情 | 辅助功能读取，包含普通输入框；读不到时 OCR 兜底（§6.3） |
| 主 | 同时可见的窗口及布局 | 还原并排或多窗口工作的情境 | 记录各窗口标识、App、标题、屏幕、位置、可见状态与操作焦点；各窗口内容独立关联 |
| 主 | 网页地址 / 标题 | 浏览研究归类 | Chrome 通过自动化（AppleScript）获取各可见窗口中选中标签的网址与标题；正文读取方式由 M0b 实测 |
| 辅 | 焦点切换、窗口标题 | 排列先后顺序 | App 激活事件配合窗口焦点与标题变化 |
| 辅 | 焦点输入框字数增减 | 补充文字变化线索 | 从已读取的输入框内容派生；不监听键盘，不把字数变化等同于成果 |
| 辅 | Chrome 历史库 | 补充页面访问与跳转来源 | 先复制再读，多 Profile；与窗口记录对照，不单凭历史库推算停留时长 |
| 辅 | 无输入、睡眠 / 唤醒 / 锁屏 | 标记状态与空白时段 | 无输入阈值默认 3 分钟（可选 1/3/5）；无输入不直接写成离开 |
| 辅 | Claude Code / Codex 会话 | 补充事情主题 | 只存会话主题等瘦字段，不当主依据 |

### 6.2 不看名单与永不读取

- 不看名单之外的 App **一律完整记录**，包括聊天、邮件和正在编辑的输入框，没有中间档。
- 不看名单里的 App 不记录内容和标题，只在时间线上留「不看」的时间占位。
- 用户随时可以修改不看名单，修改立即生效；开启一天时沿用上一次的设置。
- 以下内容**永远不读，用户也无法打开**：密码输入框（AXSecureTextField）、浏览器里的钱包插件页面（如 MetaMask，`chrome-extension://`）和密码管理器插件页面、无痕窗口。
- 只读当前可见的窗口，不读取未打开的文件或后台隐藏页面。

### 6.3 采样策略（待 M0b 实测定参数）

- 事件触发为主：焦点变化、标题变化、输入框字数变化；静止时低频采样（初始 5 秒，M0b 后调整）。
- 文字入库做去重与差分，同一屏不重复存。
- 同时可见的多个窗口分别记录，区分「正在操作」与「同时可见」；同一 App 的不同窗口保持独立标识。
- 读不到文字（Electron、自绘界面等）：先尝试开启 `AXManualAccessibility`；仍读不到时，**默认**对该窗口做本机 OCR。限频（初始每个窗口每 30 秒最多一次，并限制整体频率），图片识别后立即丢弃，不落盘。OCR 可以在设置里关闭，未授予屏幕录制权限时自动停用。
- 权限不足、窗口不可读或采样失败时，保留可用的标题与状态，并记录内容缺口；不据此编造活动描述。

### 6.4 多窗口边界

- 范围为当前活动桌面实际可见的窗口；不主动切换其他桌面，不遍历最小化或完全遮挡的窗口。
- 记录窗口所在屏幕与位置关系，支持说明「左侧网页、右侧文档」或「主屏文档、副屏参考资料」；布局变化记录时间。
- 「同时可见」不能证明用户已经阅读，也不能把多个窗口的可见时长相加计入事情时长。
- 同时可见的窗口中有一个在不看名单里时，其他窗口照常记录，该窗口只留占位，不泄露标题或内容。

## 7. 记录的结构

记录是事实，只说明观察到了什么。每条记录至少包含下列信息；没有采集到的字段标明缺失及原因，不补写成事实。

| 字段 | 要求 |
| --- | --- |
| 时间 | 开始与结束时间；采样中断或缺口单独标记 |
| 行为 | 实际观察到的动作，如窗口切换、页面显示、文字变化 |
| App 与窗口 | App 名称、窗口标识和标题；同一 App 的两个窗口分开记录 |
| 内容 | 脱敏后的文字摘录，保留来源窗口、采集时间和读取方式（辅助功能 / OCR） |
| 页面或文档 | 实际获取到的页面标题、网址、文档名称或路径；取不到路径时只列已知名称 |
| 桌面布局 | 同时可见的窗口、所在屏幕及位置关系、操作焦点；部分遮挡或内容不可读时标明 |

**原始时间线**就是按时间排列的记录。它只在没有模型可用，或用户在对话里展开某个结论的依据时才呈现。

## 8. AI

### 8.1 白天整理

- 复盘日内每 15 分钟左右（可设置）把新增记录交给「整理模型」，更新这个复盘日的**事情**列表。
- 事情用日常说法命名，如「写稳定币研究文档」「刷 X」「参加周会」；一件事情可以在一天中断断续续出现多次。
- 每件事情关联它所依据的记录，保证复盘时可以追溯；事情的时长以操作焦点计算，不叠加同时可见的窗口。
- 较长的无输入、锁屏或睡眠时段标为空白，留待复盘时询问。
- 整理结果存在本机。复盘时 AI 基于事情列表对话，追问细节时再查对应的原始记录。

### 8.2 新工作询问

- 白天整理时，若发现一件新的、有产出的工作（如「写 XX 文档」「排查 XX 问题」），持续 ≥10 分钟，且不在待办里，就弹出系统通知：「发现新工作：写 XX 文档，加入待办吗？」，带「加入 / 不用」两个按钮。
- 刷 X、吃饭、上厕所等不算新工作，不询问。
- 用户点「加入」才加入待办；点「不用」或没理会都视为不加，同一件事情当天不再询问。
- 频率上限：默认每 30 分钟最多一条（可设置）；macOS 专注模式开启时、全屏会议中不弹出。

### 8.3 复盘对话

**开场白**：打开某个复盘日时，AI 先说：

1. 今天何时开启，比计划开始时刻早或晚多少。
2. 用 3 到 5 行列出主要事情及时长。
3. 待办的状态：哪些勾掉了，哪些没有。
4. 1 到 3 个「观察 + 提问」，例如「待办『交报告』今天没勾掉，写的时候有 6 次转去推特，是卡住了吗？」。

**判断「没做好」的依据**：没勾掉的待办就是没做完；记录里观察到的情况（反复被打断、开了头没继续、同一件事拖了很久等）用来辅助判断做得怎么样。AI 不直接下结论，先以提问说出观察，用户确认或否定后，再给总结性建议。不打分，不使用「跑偏」等标签。

**对话中**：

- 用户可以追问任何细节，AI 引用对应的记录作答，依据可以展开为原始时间线。
- 对较长的空白时段，AI 主动询问在做什么；用户的回答记为**用户补充**，直接成为一件事情。
- 用户的纠正（「那段不是刷推，是在查资料」）也记为用户补充，直接改写当天的事情列表；v1 不把纠正沉淀成长期规则。
- AI 可以问：「今天这几件事情不在待办里，要加进去吗？」，用户同意才加入。
- AI 永远不替用户勾选待办。
- 可以跨复盘日提问，如「这周我在 X 上花了多久」，范围限于本机仍保留的数据。
- 每个复盘日有一个对话线程，可以随时回去接着聊。对话保存在本机，永久保留。

**语气**：中性、具体、不说教；先陈述观察到的事实，再提问。

### 8.4 模型配置

- 两个独立的模型槽位：**整理模型**（白天整理、新工作识别，频繁，宜选快而便宜的模型）和**对话模型**（复盘对话，宜选能力强的模型）。
- 支持的接入方式：
  1. **各家官方 API**：Anthropic、OpenAI、Google Gemini、xAI、DeepSeek 等，填写 API 密钥。
  2. **兼容接口**：兼容 OpenAI 或 Anthropic 格式的自定义地址 + 密钥，可接 Ollama 等本机模型或其他服务。
- 想用订阅（Claude、ChatGPT 等）时，设置页提示可以用 [magpie](https://github.com/yetone/magpie) 这类本机网关，把它的本机地址填进兼容接口。App 不依赖、不内置 magpie。提示里同时说明：记录会经过该网关，使用前应确认它不留存请求内容；ChatGPT 等订阅的接入方式是否符合服务条款，需要用户自行判断。
- API 密钥存钥匙串。通过可替换的 `ReviewProvider` 接口隔离各家差异。

### 8.5 外发

- 不看名单之外记录下来的内容都可以发给用户配置的模型，发送时不预览、不确认，也不保留发送记录（ADR 0002）。
- 写入前脱敏（§10）同样作用于外发内容。
- 除用户配置的模型地址外，App 不向任何地方发送数据，不做遥测。

### 8.6 模型不可用

- 断网、密钥失效、额度用完时，记录照常进行，一条都不丢。
- 白天整理暂停，恢复后自动补上落下的部分。
- 聊天区明确说明原因，如「模型连不上：额度已用完」；菜单栏图标有轻微状态提示，不弹窗。
- 没有配置模型时，复盘窗口只提供原始时间线，并提示去配置模型。

## 9. 界面（草案，待 Jonas 设计）

布局细节 Jonas 还要再想，以下只是目前确定的骨架。

- **菜单栏下拉**：开启一天 / 结束一天；记录状态（未开启时显示比计划晚了多少）；待办的快速查看与勾选；打开复盘窗口；修改不看名单；模型状态。
- **复盘窗口**：左边是**聊天区**，右边是**待办区**。
  - 聊天区顶部有日期切换，默认今天。
  - 待办区列出所有没做完的待办，显示已进行天数，可以新增、勾选、删除；也显示当天已勾掉的待办。
- **过往历史**：从日期切换进入，可以删除某一天（§10）。不放在主界面上。
- 界面文案使用 CONTEXT.md 中的术语。

## 10. 存储、加密与保留

| 项 | 要求 |
| --- | --- |
| 库 | 本机单库 SQLite（WAL），事件追加 + 游标，崩溃可重放 |
| 内容 | 记录、事情（关联来源记录）、用户补充、待办（含创建时间、来源、完成时间）、对话、复盘日（开启 / 结束时间、计划开始时刻） |
| 加密 | **库加密，密钥存钥匙串**；无密钥无法读库 |
| 保留 | 原始记录默认 **30 天**，可选 7 天 / 30 天 / 永不清除；事情、用户补充、待办、对话永久保留 |
| 删除某一天 | 在过往历史中操作；删除这一天的原始记录，并让用户选择是否连同事情和对话一并删除 |
| 脱敏 | 写入前：API key、私钥、助记词（BIP39 ≥12 词）、JWT、信用卡号（Luhn 校验）、网址 query 一律替换或丢弃；钱包地址是公开信息，保留 |
| 备份 / 导出 | `VACUUM INTO` 一致性快照；按日期导出 |

## 11. 隐私总览

| 记 | 不记 |
| --- | --- |
| 开启一天之后，不看名单之外所有 App 的可见窗口文字，含聊天、邮件、普通输入框（脱敏、加密） | 开启一天之前、结束一天之后的任何内容 |
| 同时可见窗口的布局、焦点与读取状态 | 不看名单里 App 的标题与内容 |
| 读不到文字时单窗口 OCR 的识别结果 | 截图图片（识别后丢弃）；全屏录屏 |
| Chrome 网址（去 query）与标题；历史库里的访问时间与跳转来源 | 无痕窗口；钱包与密码管理器插件页面 |
| 无输入 / 睡眠 / 锁屏边沿 | 密码输入框；键盘按键、鼠标轨迹、剪贴板 |
| 事情、待办、用户补充、复盘对话 | 锁屏后窗口内容 |

记录下来的内容都可能发给用户配置的模型。残余风险是未覆盖的秘密形态和第三方网关的留存，靠不看名单、永不读取项、写入前脱敏和用户对模型服务的选择来降低。辅助功能权限只授给签名的 `.app`。

## 12. 功能需求

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-01 | P0 | 首次启动引导 | 按 §5.1 顺序；模型配置可跳过，跳过后只记录、复盘窗口只给原始时间线 |
| FR-02 | P0 | 开启一天 / 结束一天 | 未开启不记录、不提醒；开启后显示与计划开始时刻的对照；忘了结束时持续到下次开启 |
| FR-03 | P0 | App 与窗口焦点、标题 | 区分 App 激活与同一 App 内的窗口切换；边沿延迟目标 ≤1s（真机待验） |
| FR-04 | P0 | 辅助功能读窗口文字 | 不看名单外完整读取，含普通输入框；密码框不读；读不到时记录缺口，不伪造内容 |
| FR-05 | P0 | OCR 兜底 | 默认开启，仅在读不到文字时识别单个窗口；限频；图片不落盘；可关闭；无屏幕录制权限时自动停用 |
| FR-06 | P0 | 多窗口与桌面布局 | 并排窗口分别记录内容与位置；区分正在操作与同时可见；不看名单内的窗口只留占位；时长不叠加 |
| FR-07 | P0 | Chrome 网址 / 标题 / 跳转来源 | 多窗口时分别关联；History 库先复制再读；无痕不采；钱包与密码管理器插件页面不读 |
| FR-08 | P0 | 无输入、睡眠、锁屏边沿 | 无输入阈值默认 3 分钟，不自动写成离开；锁屏后停止内容读取 |
| FR-09 | P0 | 不看名单 | 预置密码管理器、钱包、银行类 App；随时修改立即生效；开启一天时沿用上次设置 |
| FR-10 | P0 | 写入前脱敏 | 红队用例：库与 WAL 字节中无明文密钥 |
| FR-11 | P0 | 库加密、保留与删除 | 删除密钥后库不可读；保留期选项生效；可在过往历史删除某一天 |
| FR-12 | P0 | 模型配置 | 整理模型与对话模型分别配置；支持官方 API 与兼容接口；密钥存钥匙串 |
| FR-13 | P0 | 白天整理 | 按间隔增量更新事情列表；事情可追溯到来源记录；模型不可用时排队补整理 |
| FR-14 | P0 | 新工作询问 | 只对持续 ≥10 分钟的新工作询问；「加入 / 不用」；不理会即不加；同一事情当天不重复问；遵守频率上限与专注模式 |
| FR-15 | P0 | 待办区 | 用户新增、勾选、删除；只有用户能勾选；没做完的保留并显示已进行天数；标明来源（用户 / AI 询问后加入） |
| FR-16 | P0 | 复盘对话 | 开场白按 §8.3；观察以提问形式提出；支持追问、用户补充、纠正改写事情列表、跨天提问；依据可展开 |
| FR-17 | P0 | 原始时间线 | 无模型时可回看记录与缺口；对话中可展开任一结论的依据 |
| FR-18 | P0 | 模型不可用处理 | 记录不中断；恢复后补整理；聊天区说明原因；菜单栏轻提示，不弹窗 |
| FR-19 | P1 | 健康与缺口提示 | 权限被撤、采集中断在复盘中可见 |
| FR-20 | P1 | Claude / Codex 会话主题（辅助） | 只存主题；去重；不当主依据 |
| FR-21 | P2 | 导出与备份 | 见 §10 |

## 13. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 技术栈 | 纯 Swift，实现菜单栏 App、采集、存储与复盘；不沿用 Python 摄入原型 |
| 资源 | 目标：平均 CPU 低（M0b 实测后定具体数字）；内存常驻小；OCR 与白天整理限频 |
| 响应 | 打开复盘窗口时，开场白基于已整理好的事情列表生成，不等待整天重新处理 |
| 可靠性 | WAL；事件与游标同事务；schema 前向迁移；模型失败不影响记录 |
| 隐私 | 无击键、无剪贴板、无全屏截图；写入前脱敏；无遥测 |
| 网络 | 只连接用户配置的模型地址；未配置模型时零网络 |
| 打包 | 通用二进制（arm64 + x86_64）`.app`，`LSUIElement` 菜单栏，`SMAppService` 登录项 |

## 14. 签名与安装

- 不走 Mac App Store、不要求 Apple 开发者账号：用一张固定自签证书给 `.app` 签名。
- 历史文档称已在云端验证同一证书重建时的代码身份（designated requirement）保持一致，当前仓库缺少可复核的实现与验证产物。授权在升级后保留仍属预期，需后续真机验证。
- 代价：首次打开需右键 → 打开；无公证。**决定：不开通 Developer ID（Jonas 2026-10-29）。** 若真机验证授权不保留，则减少升级频次，升级后在 App 内引导重新授权。
- 证书与私钥只放本地，**不提交 git**。
- 需要的授权：辅助功能（必须）、自动化 → Chrome（取网址）、屏幕录制（OCR 兜底）、登录项。

## 17. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 记录不确认就外发，敏感内容被发给模型 | 隐私泄露 | 不看名单、永不读取项、写入前脱敏；用户自行选择可信的模型服务 |
| 经第三方网关（如 magpie）接入时请求被留存 | 加密库之外出现未加密副本 | 设置页提示风险；使用前核实留存设置 |
| 忘了开启一天 | 当天没有记录 | Jonas 接受此代价；菜单栏显示比计划晚了多少 |
| 新工作询问过于频繁 | 打断专注 | 持续时长门槛、频率上限、专注模式与全屏会议静默；「不用」后当天不再问 |
| AI 误判「没做好」 | 复盘让人反感或不可信 | 以待办勾选为主要依据；观察以提问形式提出，用户确认后才给建议；依据可展开 |
| 白天整理产生持续用量 | 费用或订阅额度消耗 | 整理模型可单独选择便宜模型；间隔可调 |
| Electron / 自绘界面读不到文字 | 事情归纳变弱 | `AXManualAccessibility`；OCR 兜底；缺口明确显示 |
| 自签证书授权不保留 | 每次升级要重新授权 | M0b 验证；减少升级频次，App 内引导 |
| 多窗口可见性或布局不完整 | 错认参考资料、重复计算时长 | 窗口分别标识，区分操作焦点与可见状态；时长不叠加 |
| macOS 更新改变辅助功能行为 | 读取失效 | 健康提示 + 探测版回归 |
| 电量与 CPU | 影响日常使用 | 事件驱动、OCR 与整理限频、M0b 实测 |
