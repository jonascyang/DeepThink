## 1. 一句话

Think My Day 是 Jonas 个人用的 macOS 菜单栏 App：从「开启一天」起，在本机完整记录电脑上发生的事；白天由 AI 安静地整理成一件件**事情**，并在发现新工作时询问是否加入**待办**；任何时候都可以打开复盘窗口，和 AI 对话，弄清楚今天做了什么、哪件事没做好。

它要帮 Jonas 做到两件事，也就是他的**长期方向**：遇到难题能自己拆开、想清楚，不再逃；稳定地推进手上几件重要的事。他同时推进几条**主线**（例如长期的学英语、每天的工作），所以一天不是围绕一件事，而是给每条主线定一个今天要交出的产出和时间上限；复盘时找出**逃开**的时刻，把卡住的难题拆成能回答的小问题，再定下明天的第一步。

## 2. 背景与问题

Jonas 是加密研究员，并行使用多个 AI Agent、浏览器研究、聊天工具和文档。一天结束时，他不清楚时间去了哪里、哪件事其实没做完或没好好做。只记「哪个 App 开了多久」回答不了「当时在做什么事情」；静态的报告又很难看进去，也没法当场补充和纠正。

v0.3 试图判断「跑偏」，但多次切换可能是同一项研究中的交叉查证，打开某个网站本身不说明偏离，「跑偏」这个标签对 Jonas 也没有用。他真正想知道的是：今天打算做的事做完了没有，没做完的卡在哪里。所以 v0.4 用**待办**表达意图，用**事情**还原实际发生的事，由 AI 在对话中把两者对照起来。

2026-11-01 的一次试复盘（见 [复盘方法](复盘方法.md)）发现了更深一层：Jonas 碰到抽象、没有入口的难题时，会转去做马上能看到结果的事，例如功能还没定就反复调界面、制作流程还没弄清就先让 AI 出 62 个镜头，结果最重要的事没有推进。同一次复盘也发现，问题一旦拆成具体、可以选的小问题，他能很快想得很深。所以 v0.5 围绕这两点设计：抓住逃开的时刻，用可选的小问题帮他回到难题上。

同一天还确认了：只盯一件事不符合他的工作方式。他同时推进几条线，用 AI 工作时更是一边等 AI 一边推进另一件。他难以分配时间，一是没定过每条线该占多少，二是定了也守不住；根子在于估不准一件事要多久，又拿别人的速度当标准。所以 v0.5 不用「一天一个重点」，而是给每条主线定今天的产出和时间上限，用实际用时校准估算，拿过去的自己作比较。

## 3. 目标与非目标

### 目标（v1）

1. 用户开启一天后，完整记录不看名单之外的所有 App：窗口文字、多窗口布局与焦点、网页地址等，形成可追溯的**记录**。
2. 白天增量整理：AI 定时把新增记录归纳为**事情**，复盘时打开即可对话，无需等待整天的处理。
3. 待办与主线：用户在开启一天时填写待办，并给想推进的主线定今天的产出和时间上限；AI 发现新工作时及时询问是否加入；只有用户本人能勾选完成；没做完的待办一直保留并显示已进行几天；复盘定下的明天第一步自动成为下一天对应主线的第一件待办。
4. 对话式复盘：走完四步（§8.3）：各条主线推进得怎么样、在哪里逃开了、把卡住的难题拆成能回答的小问题、定下明天第一步。观察以提问说出，用户确认后才给建议；用户可以追问、补充、纠正，可以跨天提问。
5. 全部数据在本机，库加密；写入前脱敏。
6. 模型可由用户自行配置，支持各家官方 API 与兼容接口。
7. 无需 Apple 开发者账号即可稳定安装，重装后授权尽量保留。
8. 让变化看得见：按天、按周显示三个数（§8.3），并把同类产出的实际用时和过去的自己对比，用来对照长期方向。

### 非目标（v1）

- 跑偏判定、打分、排名。
- 在用户做事时弹出提问或提醒；逃开只在复盘里说，不在当下打断。
- 周期性全屏截图与录屏；击键监听；剪贴板监听。
- 跨设备同步、iCloud、账号体系；iPhone。
- Mac App Store 分发。
- 自带或自训练模型；内置订阅转接口的能力（交给 magpie 等外部工具）。
- 发送记录 / 外发审计界面。
- 日历等电脑之外的数据源；电脑之外的事情靠复盘对话里的用户补充。
- 解密 ChatGPT Mac 缓存；把 Claude Desktop / Muse 等当作有完整日志的一等数据源。

## 5. 用户旅程

### 5.1 首次启动（只出现一次）

1. **系统授权**：辅助功能（必须）、自动化 → Chrome（取网址）、屏幕录制（OCR 兜底用）、开机自动启动。缺少非必须授权时可以继续，相应能力标为不可用。不请求完全磁盘访问权限（Chrome 历史库见 §6.1）。
2. **计划开始时刻**：「你的一天一般从几点开始？」时区自动识别，可修改。
3. **长期方向**：「一年后，你最希望自己比现在强在哪？」给出几个选项（做成事、思考能力、专注和执行、某个专业能力、生活状态），可以多选，也可以自己写；可以跳过，之后在设置里改。Jonas 选的是思考能力、专注和执行（2026-11-01）。
4. **配置模型**：选择官方 API 或填写兼容接口（见 §8.4），页面上提示可以用 magpie 接入订阅。可以跳过；跳过后只记录，不整理，也不能复盘。
5. **确认不看名单**：预先放入密码管理器、钱包和银行类 App，用户可以移出或添加。
6. 进入第一次「开启一天」。

### 5.2 开启一天

- 用户点菜单栏的「开启一天」，打开开启面板：
  - **待办**：列出所有没做完的待办及已进行天数，可以新增，也可以不填。上一次复盘定下的明天第一步排在最前面。
  - **主线**：列出用户的几条主线。对今天想推进的主线，各定一个**今天的产出**（做到什么算完成，能检查）和**时间上限**；时间上限默认取这条主线过去同类产出的实际用时，第一次用时由用户猜。可以只填一部分，也可以都不填。
  - **不看名单**：沿用上一次的设置，可以修改。
  - 按钮「开启一天！」。
- 点了之后才开始记录。没有开启时不记录任何内容，也**不提醒**；用户打开菜单栏时显示「比计划晚了 X」。
- 开启后显示一次与计划开始时刻的对照，如「比计划晚 1 小时 30 分」「比计划早 20 分」，语气中性，不评价。

### 5.3 白天

- App 静默记录，不打扰用户。逃开只在复盘时说，白天不提醒。
- AI 每 15 分钟左右整理一次新增记录（§8.1）。
- 发现新工作时弹通知询问是否加入待办（§8.2），这是白天唯一的打断。
- 用户随时可以在菜单栏或复盘窗口里增删、勾选待办，修改不看名单。

### 5.4 结束一天

- 用户点「结束一天」，停止记录。
- 忘了点时，这个复盘日持续到下一次「开启一天」为止；中间睡觉等时段在记录里表现为无输入或睡眠。

### 5.5 复盘

- 任何时间都可以打开复盘窗口，不限于晚上，也可以复盘一天中途。
- AI 开场，用户对话，详见 §8.3。

### 5.6 回看历史

- 通过日期切换回看保留期内任意一个复盘日，也可以在对话里直接问「上周三我在做什么」。
- 在过往历史里可以删除某一天（§10）。

## 6. 采集方案

### 6.1 信号分层

| 层 | 信号 | 用途 | 说明 |
| --- | --- | --- | --- |
| 主 | 窗口可见文字 | 还原内容，支持归纳事情 | 辅助功能读取，包含普通输入框；读不到时 OCR 兜底（§6.3） |
| 主 | 同时可见的窗口及布局 | 还原并排或多窗口工作的情境 | 记录各窗口标识、App、标题、屏幕、位置、可见状态与操作焦点；各窗口内容独立关联 |
| 主 | 网页地址 / 标题 | 浏览研究归类 | Chrome 通过自动化（AppleScript）获取各可见窗口中选中标签的网址与标题；正文由辅助功能读取，M0b 实测可读，无需额外设置 |
| 辅 | 焦点切换、窗口标题 | 排列先后顺序 | App 激活事件配合窗口焦点与标题变化 |
| 辅 | 焦点输入框字数增减 | 补充文字变化线索 | 从已读取的输入框内容派生；不监听键盘，不把字数变化等同于成果 |
| 辅 | 每个窗口的操作事实 | 让 AI 分辨在输入、在等回复、在阅读还是没有操作 | 按分钟汇总：输入框增删字数与清空次数、窗口新增内容字数、鼠标滚动与点击次数（只数次数，不记位置）、没有操作的秒数；采集时不判断在做什么（Jonas 2026-10-31） |
| 辅 | 打开的文件 | 知道看的是什么、从哪来 | 窗口的文档路径、访达所在文件夹与选中项；类型、大小、创建时间、下载来源（去 query）与下载时间；「为什么看」交给 AI |
| 辅（可选） | Chrome 历史库 | 补充页面访问与跳转来源 | 需要完全磁盘访问权限（M0b：没有这项权限时系统拒绝访问），默认不请求；用户在设置里自行开启后，先复制再读，多 Profile；与窗口记录对照，不单凭历史库推算停留时长 |
| 辅 | 无输入、睡眠 / 唤醒 / 锁屏 | 标记状态与空白时段 | 无输入阈值默认 3 分钟（可选 1/3/5）；无输入不直接写成离开 |
| 辅 | Claude Code / Codex 会话 | 补充事情主题 | 只存会话主题等瘦字段，不当主依据 |

### 6.2 不看名单与永不读取

- 不看名单之外的 App **一律完整记录**，包括聊天、邮件和正在编辑的输入框，没有中间档。
- 不看名单里的 App 不记录内容和标题，只记 App 名，在时间线上留「不看：某 App」的时间占位（Jonas 2026-10-31）。
- 用户随时可以修改不看名单，修改立即生效；开启一天时沿用上一次的设置。
- 以下内容**永远不读，用户也无法打开**：密码输入框（AXSecureTextField）、浏览器里的钱包插件页面（如 MetaMask，`chrome-extension://`）和密码管理器插件页面、无痕窗口。
- 只读当前可见的窗口，不读取未打开的文件或后台隐藏页面。

### 6.3 采样策略

- 事件触发为主：焦点变化、标题变化、输入框字数变化；静止时低频采样，间隔 5 秒。M0b 实测一次读取全部可见窗口中位约 90–130 ms，平均 CPU 0.5–1.3%。Chrome 大页面读取较慢（约 21% 到 400 ms 上限），为它单独限时或只读可视区域。
- 文字入库做去重与差分，同一屏不重复存。
- 输入框只记发出去的内容：输入框被清空（通常是发送）前的最后一版记一次，打字过程中的中间状态不入库，输入法未上屏的拼音不入库。界面里不断跳动的计时、进度文字（如「已处理 5 分钟 56 秒」）不反复入库。原因：用户自己写下的话是复盘判断「有没有思考」的主要依据；2026-10-31 实测，中间状态和拼音让同一句话入库了五六次。
- 同时可见的多个窗口分别记录，区分「正在操作」与「同时可见」；同一 App 的不同窗口保持独立标识。
- 判断文字是否可见（M0b 实测，Chromium / Electron 必须这样处理）：
  - 以元素坐标为准，不信任普通文字的 `AXVisibleCharacterRange`；该属性只用于裁剪可编辑控件里的长文本。
  - 按钮、链接、标题的标题只在叶子元素上读取，避免与子元素文字重复。
  - 宽或高小于 2 pt 的元素视为已滚出视野；按滚动区域（AXScrollArea、AXWebArea）边界裁剪。
  - 单行标签可能包含被省略号截掉的全文：**记录全文**（Jonas 2026-10-31），发给模型前再按需要裁剪。
- 读不到文字（Electron、自绘界面等）：先尝试开启 `AXManualAccessibility`；仍读不到时，**默认**对该窗口做本机 OCR。限频（初始每个窗口每 30 秒最多一次，并限制整体频率），单次识别超时 10 秒，图片识别后立即丢弃，不落盘。OCR 结果标明读取方式。OCR 可以在设置里关闭，未授予屏幕录制权限时自动停用。M0b 实测：Cursor 类 Electron 编辑器开启 `AXManualAccessibility` 前读到 0 字、开启后正常，这一步必须保留；测到的 App 都能用辅助功能读到文字，OCR 半小时触发约 2 次；OCR 平均置信度 0.3–0.6，只作兜底。
- 屏幕窗口与辅助功能窗口对不上时，该窗口记为不可读并记录缺口，不悄悄丢弃。
- 权限不足、窗口不可读或采样失败时，保留可用的标题与状态，并记录内容缺口；不据此编造活动描述。

### 6.4 多窗口边界

- 范围为当前活动桌面实际可见的窗口；不主动切换其他桌面，不遍历最小化或完全遮挡的窗口。
- 记录窗口所在屏幕与位置关系，支持说明「左侧网页、右侧文档」或「主屏文档、副屏参考资料」；布局变化记录时间。
- 「同时可见」不能证明用户已经阅读，也不能把多个窗口的可见时长相加计入事情时长。
- 同时可见的窗口中有一个在不看名单里时，其他窗口照常记录，该窗口只留占位和 App 名，不泄露标题或内容。

## 7. 记录的结构

记录是事实，只说明观察到了什么。每条记录至少包含下列信息；没有采集到的字段标明缺失及原因，不补写成事实。

| 字段 | 要求 |
| --- | --- |
| 时间 | 开始与结束时间；采样中断或缺口单独标记 |
| 行为 | 实际观察到的动作，如窗口切换、页面显示、文字变化 |
| App 与窗口 | App 名称、窗口标识和标题；同一 App 的两个窗口分开记录 |
| 内容 | 脱敏后的文字摘录，保留来源窗口、所在屏幕与位置、采集时间和读取方式（辅助功能 / OCR） |
| 页面或文档 | 实际获取到的页面标题、网址、文档名称或路径；取不到路径时只列已知名称 |
| 桌面布局 | 同时可见的窗口、所在屏幕及位置关系、操作焦点；部分遮挡或内容不可读时标明 |

**原始时间线**就是按时间排列的记录。它只在没有模型可用，或用户在对话里展开某个结论的依据时才呈现。

## 8. AI

### 8.1 白天整理

- 复盘日内每 15 分钟左右（可设置）把新增记录交给「整理模型」，更新这个复盘日的**事情**列表。新增记录按全天去重后再发送。M0b 粗估上限随使用场景相差约 4 倍：AI 对话为主时每次约 9 千 token，看网页为主时每次约 3.5 万 token；10 小时约 37 万–140 万 token。整理模型宜选便宜模型，必要时先在本机压缩。
- 事情用日常说法命名，如「写稳定币研究文档」「刷 X」「参加周会」；一件事情可以在一天中断断续续出现多次。
- 每件事情关联它所依据的记录，保证复盘时可以追溯；事情的时长以操作焦点计算，不叠加同时可见的窗口。
- 较长的无输入、锁屏或睡眠时段标为空白，留待复盘时询问。
- 整理结果存在本机。复盘时 AI 基于事情列表对话，追问细节时再查对应的原始记录。
- 整理时同时标出：每件事情属于哪条**主线**，各条主线的实际用时；疑似**逃开**的时刻，即**球在用户手里**时停住后转去做别的事，并且一段时间没有回来；以及多久之后回来。「球在用户手里」指 AI 已经回复、在等用户判断或回答（窗口新内容停止增长、显示已完成），或者是没有 AI 参与、本来就要用户自己做的事。AI 还在处理时切到别的事，是正常的并行，不算逃开。这些只是复盘的线索，白天不提醒用户。初始门槛：球在用户手里时停住 ≥5 分钟后切走，10 分钟内没有回来；使用后调整。

### 8.2 新工作询问

- 白天整理时，若发现一件新的、有产出的工作（如「写 XX 文档」「排查 XX 问题」），持续 ≥10 分钟，且不在待办里，就弹出系统通知：「发现新工作：写 XX 文档，加入待办吗？」，带「加入 / 不用」两个按钮。
- 刷 X、吃饭、上厕所等不算新工作，不询问。
- 用户点「加入」才加入待办；点「不用」或没理会都视为不加，同一件事情当天不再询问。
- 频率上限：默认每 30 分钟最多一条（可设置）；macOS 专注模式开启时、全屏会议中不弹出。

### 8.3 复盘对话

**依据**：记录、事情、待办、主线及其今天的产出和时间上限、长期方向，以及过去复盘记下的经验。具体怎么问、往下追问到哪一层，见 [复盘方法](复盘方法.md)。

**开场**：AI 先用两三行说：何时开启（与计划开始时刻对照），主要事情及时长，各条主线今天的产出做到了没有。

**四步**：一次只问一个问题；每个问题给 2–4 个可选答案，外加「我自己说」；显示「第几个问题，共几个」，让用户知道复盘有尽头。

1. **各条主线推进得怎么样**：每条主线今天的产出完成了没有，实际用时和时间上限比是多少，做到哪一步。没有定产出的主线，只看它花了多少时间、做到哪一步。
2. **在哪里逃开了**：说出一两个球在用户手里时切走的时刻，例如「20:30 ChatGPT 已经把 62 个镜头交给你，你看了 6 分钟，接着去刷 X，11 分钟后才回来。是卡在哪里了？」用户确认、否定或补充。
3. **把难题拆小**：把卡住的那个难题拆成一个现在就能回答的小问题，让用户当场想一想；需要时再往下追问一层，找到根本原因。得出的做法可以记成一条**经验**，用户确认才记，可以改写。
4. **明天第一步**：给出几个具体的第一步供用户挑选；选定后自动成为下一个复盘日对应主线的第一件待办，开启一天时默认作为这条主线今天的产出。

最后给一个小结：记下的经验、明天第一步、用户对今天状态的一句话。整个复盘控制在几分钟内。

**三个数**：**完成率**是定了产出的主线里完成了几成；**估算比**是实际用时与时间上限之比，用来校准下一次的上限；**回来用时**是每次逃开到回来所用的时间，取中位数。按天和按周显示；每周把同类产出的实际用时和过去的自己对比，让进步看得见。比较对象永远是用户过去的自己，不是别人；不打分，不设默认目标线。

**判断「没做好」的依据**：没勾掉的待办就是没做完；记录里观察到的情况（反复被打断、开了头没继续、同一件事拖了很久等）用来辅助判断做得怎么样。AI 不直接下结论，先以提问说出观察，用户确认或否定后，再给总结性建议。不打分，不使用「跑偏」等标签。逃开同样只以提问说出，用户确认才算，不计入任何分数。

**对话中**：

- 用户可以追问任何细节，AI 引用对应的记录作答，依据可以展开为原始时间线。
- 对较长的空白时段，AI 主动询问在做什么；用户的回答记为**用户补充**，直接成为一件事情。
- 用户的纠正（「那段不是刷推，是在查资料」）也记为用户补充，直接改写当天的事情列表；v1 不把纠正沉淀成长期规则。
- AI 可以问：「今天这几件事情不在待办里，要加进去吗？」，用户同意才加入。
- AI 永远不替用户勾选待办。
- **经验**由用户确认、用自己的话写下，永久保留；以后遇到相似情况（同一件事情、同类卡点），AI 在复盘里把相关的经验拿出来对照。
- 可以跨复盘日提问，如「这周我在 X 上花了多久」，范围限于本机仍保留的数据。复盘最近 7 天或自定义范围时，看反复出现的卡点和两个数的变化，并对照长期方向。
- 每个复盘日有一个对话线程，可以随时回去接着聊。对话保存在本机，永久保留。

**语气**：中性、具体、不说教；先陈述观察到的事实，再提问。

### 8.4 模型配置

- 两个独立的模型槽位：**整理模型**（白天整理、新工作识别，频繁，宜选快而便宜的模型）和**对话模型**（复盘对话，宜选能力强的模型）。
- 支持的接入方式：
  1. **各家官方 API**：Anthropic、OpenAI、Google Gemini、xAI、DeepSeek 等，填写 API 密钥。
  2. **兼容接口**：兼容 OpenAI 或 Anthropic 格式的自定义地址 + 密钥，可接 Ollama 等本机模型或其他服务。
- 想用订阅（Claude、ChatGPT 等）时，设置页提示可以用 [magpie](https://github.com/yetone/magpie) 这类本机网关，把它的本机地址填进兼容接口。App 不依赖、不内置 magpie。提示里同时说明：记录会经过该网关；ChatGPT 等订阅的接入方式是否符合服务条款，需要用户自行判断。
- magpie 的留存行为（2026-10-30 读源码 `48edbcb` 核实）：默认不把请求和回复正文写入磁盘，用量日志与路由历史只有模型、token、耗时等元数据；「请求归档」「OTLP 导出」及插件观察者能拿到正文，均默认关闭，设置页提示保持关闭。例外是 **Claude 订阅通道**：magpie 驱动本机 `claude` 时会保留 Claude Code 的会话文件（含完整提示词，即我们发送的记录），位于 `~/.claude/projects/` 下 magpie 的工作目录，供一小时内续接对话，之后删除；magpie 异常退出时，残留文件要到它下次启动才被清理。这段时间里记录会以未加密的形式出现在加密库之外，Jonas 已接受（2026-10-30）。
- API 密钥存钥匙串。通过可替换的 `ReviewProvider` 接口隔离各家差异。

### 8.5 外发

- 不看名单之外记录下来的内容都可以发给用户配置的模型，发送时不预览、不确认，也不保留发送记录（ADR 0002）。
- 写入前脱敏（§10）同样作用于外发内容。
- 除用户配置的模型地址外，App 不向任何地方发送数据，不做遥测。

### 8.6 模型不可用

- 断网、密钥失效、额度用完时，记录照常进行，一条都不丢。
- 白天整理暂停，恢复后自动补上落下的部分。
- 聊天区明确说明原因，如「模型连不上：额度已用完」；菜单栏图标有轻微状态提示，不弹窗。
- 没有配置模型时，复盘窗口只提供原始时间线，并提示去配置模型。

## 9. 界面（结构已定，视觉待定）

结构以可点击原型 `prototypes/ui/think-my-day-v7.html` 为参考，原则是对 ADHD 友好：一屏一个主角、时间看得见、少读字、只给下一步、看得到进展、每件事情固定一种颜色和图标。配色、字体等视觉风格等核心循环跑通后再定：功能没定时打磨视觉，没有标准判断好坏（2026-11-01）。本节取代 `docs/UI-构思.md` 中与之不同的部分。

- **侧栏**：今天 / 复盘 / 历史 / 设置。
- **今天**：
  - 未开启：只显示开启面板：带过来的待办、各条主线今天的产出和时间上限、今天不看的 App、「开启一天」。
  - 记录中：最上面是正在做的事情和它所属的主线，这一段专注了多久、这条主线今天用了多少（对比时间上限）；同时在做的其他事情只占一行；下面是按真实时刻排开的今天的时间条，可以悬停查看、点击跳到历史；右栏是各条主线今天的产出和进度、「下一件」待办；「今天做成的」列出完成的产出和勾掉的待办。
  - 已结束：一句收尾和「去复盘」。
- **复盘**：范围可选今天 / 昨天 / 最近 7 天 / 自定义；聊天区按 §8.3 的四步进行，答案是大按钮；右栏是这段时间的事情分布、两个数和记下的经验。
- **历史**：按日期切换；时间线上每段的长度和时长成比例，离开的时段单独标出；细节点开才看；可以按事情查看；可以删除某一天（§10）。
- **菜单栏下拉**：开启一天 / 结束一天；记录状态与呼吸灯（未开启时显示比计划晚了多少）；各条主线今天的产出和用时；待办的快速查看与勾选；打开主窗口。
- 界面文案使用 CONTEXT.md 中的术语。

## 10. 存储、加密与保留

| 项 | 要求 |
| --- | --- |
| 库 | 本机单库 SQLite（WAL），事件追加 + 游标，崩溃可重放 |
| 内容 | 记录、事情（关联来源记录与主线）、用户补充、待办（含创建时间、来源、完成时间）、对话、复盘日（开启 / 结束时间、计划开始时刻）、主线、每天各主线的产出与时间上限、长期方向、经验 |
| 加密 | **库加密，密钥存钥匙串**；无密钥无法读库 |
| 保留 | 原始记录默认 **30 天**，可选 7 天 / 30 天 / 永不清除；事情、用户补充、待办、对话、经验永久保留 |
| 删除某一天 | 在过往历史中操作；删除这一天的原始记录，并让用户选择是否连同事情和对话一并删除 |
| 脱敏 | 写入前：API key、私钥、助记词（BIP39 ≥12 词）、JWT、信用卡号（Luhn 校验）、网址 query 一律替换或丢弃；钱包地址是公开信息，保留 |
| 备份 / 导出 | `VACUUM INTO` 一致性快照；按日期导出 |

## 11. 隐私总览

| 记 | 不记 |
| --- | --- |
| 开启一天之后，不看名单之外所有 App 的可见窗口文字，含聊天、邮件、普通输入框（脱敏、加密） | 开启一天之前、结束一天之后的任何内容 |
| 同时可见窗口的布局、焦点与读取状态；不看名单里的 App 名 | 不看名单里 App 的标题与内容 |
| 读不到文字时单窗口 OCR 的识别结果 | 截图图片（识别后丢弃）；全屏录屏 |
| Chrome 网址（去 query）与标题；用户开启后，历史库里的访问时间与跳转来源 | 无痕窗口；钱包与密码管理器插件页面 |
| 无输入 / 睡眠 / 锁屏边沿 | 密码输入框；键盘按键、鼠标轨迹、剪贴板 |
| 事情、待办、用户补充、复盘对话 | 锁屏后窗口内容 |

记录下来的内容都可能发给用户配置的模型。残余风险是未覆盖的秘密形态和第三方网关的留存，靠不看名单、永不读取项、写入前脱敏和用户对模型服务的选择来降低。辅助功能权限只授给签名的 `.app`。

## 12. 功能需求

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-01 | P0 | 首次启动引导 | 按 §5.1 顺序；模型配置可跳过，跳过后只记录、复盘窗口只给原始时间线 |
| FR-02 | P0 | 开启一天 / 结束一天 | 未开启不记录、不提醒；开启时可以给主线定今天的产出和时间上限；开启后显示与计划开始时刻的对照；忘了结束时持续到下次开启 |

| FR-04 | P0 | 辅助功能读窗口文字 | 不看名单外完整读取，含普通输入框；密码框不读；读不到时记录缺口，不伪造内容 |

| FR-06 | P0 | 多窗口与桌面布局 | 并排窗口分别记录内容与位置；区分正在操作与同时可见；不看名单内的窗口只留占位；时长不叠加 |
| FR-07 | P0 | Chrome 网址 / 标题 | 多窗口时分别关联；无痕不采；钱包与密码管理器插件页面不读 |

| FR-13 | P0 | 白天整理 | 按间隔增量更新事情列表；事情可追溯到来源记录；模型不可用时排队补整理 |
| FR-14 | P0 | 新工作询问 | 只对持续 ≥10 分钟的新工作询问；「加入 / 不用」；不理会即不加；同一事情当天不重复问；遵守频率上限与专注模式 |
| FR-15 | P0 | 待办区 | 用户新增、勾选、删除；只有用户能勾选；没做完的保留并显示已进行天数；标明来源（用户 / AI 询问后加入 / 复盘定下的明天第一步）；只突出下一件 |
| FR-16 | P0 | 复盘对话 | 按 §8.3 的开场和四步；一次一个问题，带 2–4 个可选答案和「我自己说」；观察以提问形式提出；支持追问、用户补充、纠正改写事情列表、跨天提问；依据可展开；明天第一步自动成为下一天的第一件待办 |
| FR-17 | P0 | 原始时间线 | 无模型时可回看记录与缺口；对话中可展开任一结论的依据 |
| FR-18 | P0 | 模型不可用处理 | 记录不中断；恢复后补整理；聊天区说明原因；菜单栏轻提示，不弹窗 |
| FR-19 | P1 | 健康与缺口提示 | 权限被撤、采集中断在复盘中可见 |
| FR-20 | P1 | Claude / Codex 会话主题（辅助） | 只存主题；去重；不当主依据 |
| FR-21 | P2 | 导出与备份 | 见 §10 |
| FR-22 | P0 | 长期方向 | 首次启动时可设置，可以跳过；设置里可以改；复盘时用来对照 |
| FR-23 | P0 | 主线、今天的产出与时间上限 | 用户维护几条主线；开启一天时可以给每条定今天的产出和时间上限，上限默认取过去同类产出的实际用时；当天可以修改；白天整理把事情归到主线 |
| FR-24 | P0 | 逃开识别 | 白天整理标出球在用户手里时切走的时刻和回来用时；AI 还在处理时的切换不算；只在复盘里以提问说出，用户可以否定；白天不提醒 |
| FR-25 | P0 | 输入框只记发出的内容 | 同一句话不因打字过程重复入库；输入法未上屏的拼音不入库；跳动的计时、进度文字不反复入库 |
| FR-26 | P1 | 经验 | 用户确认后才记，可以改写；永久保留；相似情况时在复盘里拿出来 |
| FR-27 | P1 | 三个数与每周校准 | 完成率、估算比、回来用时；按天和按周显示；每周对比同类产出的实际用时；参照过去的自己；不打分 |

以上为后续实现的验收要求，不代表已经通过验证。

## 13. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 技术栈 | 纯 Swift，实现菜单栏 App、采集、存储与复盘；不沿用 Python 摄入原型 |
| 资源 | 平均 CPU < 2%，p95 < 5%；内存 < 150 MB；OCR 与白天整理限频（M0b 探测程序实测：平均 0.5–1.3%，p95 ≤ 4%，约 53–63 MB） |
| 响应 | 打开复盘窗口时，开场白基于已整理好的事情列表生成，不等待整天重新处理 |
| 可靠性 | WAL；事件与游标同事务；schema 前向迁移；模型失败不影响记录 |
| 隐私 | 无击键、无剪贴板、无全屏截图；写入前脱敏；无遥测 |
| 网络 | 只连接用户配置的模型地址；未配置模型时零网络 |
| 打包 | 通用二进制（arm64 + x86_64）`.app`，`LSUIElement` 菜单栏，`SMAppService` 登录项 |

## 14. 签名与安装

- 不走 Mac App Store、不要求 Apple 开发者账号：用一张固定自签证书给 `.app` 签名。
- **M0b 已在真机验证（2026-10-30 / 31）**：用固定证书签名，指定要求为 identifier 加证书 leaf；重新构建安装约 10 次，辅助功能与屏幕录制授权都保留。签名脚本第一次使用钥匙串里的证书时需点「始终允许」。换证书才需要重新授权。
- 代价：首次打开需右键 → 打开；无公证。**决定：不开通 Developer ID（Jonas 2026-10-29）。**

- 需要的授权：辅助功能（必须）、自动化 → Chrome（取网址）、屏幕录制（OCR 兜底）、登录项。

## 17. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 记录不确认就外发，敏感内容被发给模型 | 隐私泄露 | 不看名单、永不读取项、写入前脱敏；用户自行选择可信的模型服务 |
| 经第三方网关（如 magpie）接入时请求被留存 | 加密库之外出现未加密副本 | magpie 默认不留存正文，请求归档、OTLP 导出保持关闭；Claude 订阅通道的会话文件约一小时后删除，在设置页说明这一点 |
| 忘了开启一天 | 当天没有记录 | Jonas 接受此代价；菜单栏显示比计划晚了多少 |
| 把正常的切换误判成逃开 | 复盘让人觉得被指责，不想用 | 只在复盘里以提问说出，用户可以否定；不计分；门槛用真实记录调整 |
| 拆题变成说教，或者问题太多 | 不想复盘 | 一次一个问题，带可选答案；四步内结束；显示还剩几个问题 |
| 新工作询问过于频繁 | 打断专注 | 持续时长门槛、频率上限、专注模式与全屏会议静默；「不用」后当天不再问 |
| AI 误判「没做好」 | 复盘让人反感或不可信 | 以待办勾选为主要依据；观察以提问形式提出，用户确认后才给建议；依据可展开 |
| 白天整理产生持续用量 | 费用或订阅额度消耗（M0b 上限估计每天 37 万–140 万 token） | 整理模型可单独选择便宜模型；间隔可调；发送前全天去重 |
| Electron / 自绘界面读不到文字 | 事情归纳变弱 | `AXManualAccessibility`（M0b：Cursor 类编辑器开启后才可读）；OCR 兜底；缺口明确显示 |
| 换证书导致授权失效 | 要重新授权 | M0b 已验证同一证书重建会保留授权；证书只在本地保管、不轮换 |
| 多窗口可见性或布局不完整 | 错认参考资料、重复计算时长 | 窗口分别标识，区分操作焦点与可见状态；时长不叠加 |
| macOS 更新改变辅助功能行为 | 读取失效 | 健康提示 + 探测版回归 |
| 电量与 CPU | 影响日常使用 | 事件驱动、OCR 与整理限频；M0b 实测平均 CPU 0.5–1.3% |
