# DeepThink · PRD v0.2：数据获取

**版本：** PRD v0.2  
**状态：** 草案（brainstorm 结论整理）  
**Owner：** Jonas C  
**日期：** 2026-10-28  
**平台：** 仅 macOS，SwiftUI 原生，全部 Swift 实现  
**取代：** [PRD v0.1](PRD-采集与存储.md) 的产品定位与采集方案。v0.1 的事件模型、幂等写入、脱敏先于写入等工程原则继续有效。

本版只定**数据怎么获取、怎么保护、怎么交给 AI**。AI 理解的具体设计和复盘界面另写文档。

## 1. 产品定位

> **本地版 Littlebird + ADHD 复盘：让 AI 看着你的电脑，理解你在做什么。**

DeepThink 常驻后台，读取屏幕上的内容，理解你当时在做什么任务、实际做了什么、什么时候跑神了，然后主动还原你的一天。

### 和 v0.1 的区别

| | v0.1 | v0.2 |
| --- | --- | --- |
| 目标 | 采集与存储的底座，不做复盘 | 让 AI 理解你的一天，面向 ADHD 复盘 |
| 屏幕内容 | 只记窗口标题 | 读屏幕文字，读不到时识别窗口截图 |
| AI | 不在范围内 | 必需。判断意图和跑神只能靠模型 |
| 日志摄入 | Python 摄入 Claude Code、Codex、Chrome、Biome | 只读 Chrome 历史，全部用 Swift |
| 隐私底线 | 不截图、不存 prompt | 允许截图识别（图片立即删除）；严防密码、私钥、助记词 |

### 和 Littlebird 的区别

[Littlebird](https://littlebird.ai/facts) 是目前最接近的产品：用辅助功能每隔几秒读当前窗口的文字。我们在三点上不同：

1. **数据只存在本机**。Littlebird 存在 AWS。
2. **记录"你做了什么"，不只是"你看到了什么"**。区分阅读和输入，记录选中和产出。
3. **主动还原一天**。Littlebird 是你问它才答；我们为 ADHD 主动整理任务、行为和跑神链条。

## 2. 用户与问题

主要用户是 Jonas 本人：加密研究员，在 Chrome、AI 工具和多个 App 之间频繁切换，有 ADHD。

要解决的问题：**同时开着很多页面来回切，可能什么都没做成，事后也说不清楚。** 系统要能回答：

- 我当时想做什么任务？
- 我实际做了什么？读了什么、写了什么、产出了什么？
- 在哪里偏离了，怎么偏离的？比如"研究文章 → 推特 → 25 分钟"。

只有 App 名和网址回答不了这些问题，必须知道屏幕上的内容。

## 3. 数据来源

一共五路，按重要程度排列。

### 3.1 屏幕文字（辅助功能）· P0 · 主力

用 macOS 辅助功能接口读取窗口里的文字和界面结构。这是读屏软件用的接口，Screenpipe 和 Littlebird 也以它为主要来源。

**读什么**

- 当前窗口：标题、可见文字、界面结构（标题、正文、列表、输入框）。
- 文档路径或网址（App 提供时）。
- 选中的文字。
- **区分阅读和输入**：输入框、编辑器里新出现的文字记为"产出"，其余记为"阅读"。

**什么时候读**

- **事件驱动为主**：切换窗口、窗口标题变化、内容变化、选中变化时读取。
- **低频轮询兜底**：每隔几秒检查一次，防止漏掉不发通知的 App。具体间隔由 M0 探测决定。
- **内容没变就不存**：对文字做哈希去重，只存变化的部分。

**需要特殊处理的 App**

- **Electron 类 App**（飞书、Slack、VS Code、Notion 等）默认不开放辅助功能信息。由我们设置 `AXManualAccessibility` 开关打开。这是 Electron 官方支持的做法，会让该 App 稍慢一些。
- **Chrome**：网页内容同样需要打开辅助功能支持才能读到。

### 3.2 窗口截图识别 · P0 · 兜底

辅助功能读不出文字时（Figma、图片、扫描版 PDF、视频、远程桌面，以及部分常用 App），用这一路补上。

规则：

1. **只在辅助功能读出的文字低于阈值时触发**。阈值由 M0 探测决定。
2. **只截当前那一个窗口**，不截全屏，也不定时截图。
3. **画面没变就不重复截**。
4. **在本机识别**：用苹果系统自带的 Vision 文字识别，图片不离开电脑。
5. **识别完立即删除图片**，只保留识别出的文字。数据库里永远没有图片。
6. 钱包、密码管理器等排除名单中的 App **不截**。

需要额外申请「屏幕录制」授权。用户不授权时，这一路关闭，其余照常工作。

### 3.3 Chrome 历史 · P0

Chrome 自己的历史数据库里有网址、标题、访问时间，以及**从哪个页面跳过来的**（跳转来源）。这可以还原"文章 → 推特 → 刷了 20 分钟"这种链条，屏幕文字很难做到。

- 支持多个 Profile。
- 先复制再读取，不锁住 Chrome 正在使用的数据库。
- 无痕窗口不会写进 Chrome 历史，所以天然不采。
- 网址的 query 和 fragment 默认丢弃。
- Brave、Edge 使用相同格式，可以用同一套代码支持（P2）。

### 3.4 节奏信号 · P0

| 信号 | 实现 | 用途 |
| --- | --- | --- |
| App 切换 | NSWorkspace 通知 | 切换次数、时间边界 |
| 离开键盘（AFK） | `CGEventSource` 空闲秒数，阈值 180 秒；不监听键盘内容 | 区分"开着"和"在用" |
| 睡眠 / 唤醒 / 锁屏 | 系统通知 | 时间线上的空白 |

### 3.5 其他可见窗口 · P2

很多人在副屏放资料、在主屏写作。低频读取其他屏幕上可见的窗口，标记为"参考内容"，和正在操作的窗口分开。

### 3.6 用户主动输入 · P1

- **开工意图**（可选）：开始做事前写一句"现在要做 X"，作为判断跑神的依据。不写也能用。
- **想法停车场**：全局快捷键，一秒存下走神时冒出的念头。

## 4. 明确不做

| 不做 | 原因 |
| --- | --- |
| Chrome 插件 | 辅助功能读正文 + Chrome 历史已覆盖；插件需要另一套代码和安装流程 |
| 解析 Claude Code / Codex 日志 | 你输入的 prompt 已显示在屏幕上，读屏会读到。以后如果发现 AI 看不懂 agent 协作，再作为独立模块加入 |
| 定时截全屏、录屏 | 低效；只在读不到文字时截单个窗口 |
| 记录击键内容、鼠标轨迹、剪贴板 | 不需要，且风险高 |
| Python 摄入 | 全部用 Swift 实现 |
| Biome、屏幕使用时间库 | 需要完全磁盘访问，且苹果在持续变更；不作为数据来源 |
| 会议音频转录 | 暂不做，见开放问题 |

## 5. 隐私

### 底线

**只要不泄露密码、私钥、助记词这类高度敏感的信息，其他内容都可以采集。**

### 读取之前就跳过

- 所有密码输入框。系统将它们标记为安全文本框（`AXSecureTextField`），一律不读。
- 排除名单里的 App 整个不读、不截：1Password、Bitwarden、LastPass、钥匙串、密码 App、KeePassXC、Ledger Live、Trezor Suite 等，用户可以补充。
- 浏览器里的钱包插件页面（`chrome-extension://` 下的 MetaMask 等）整个跳过。

### 存储之前替换

| 类型 | 识别方式 |
| --- | --- |
| 助记词 | 用完整的 BIP39 词表检测连续 12 个及以上的词表词 |
| 私钥 | 64 位十六进制、xprv、WIF、PEM 私钥 |
| API 密钥 / token | Anthropic、OpenAI、GitHub、AWS、Slack、JWT 等常见格式 |
| 信用卡号 | 卡号格式 + Luhn 校验 |
| 网址 query | 默认丢弃 |

钱包地址是公开信息，保留。研究时需要用到。

### 残余风险

- 格式少见的密钥，规则可能拦不住。
- 普通文字里出现的敏感内容（比如粘贴在聊天框里的密码）可能被读到。如果命中上面的格式会被替换，否则会入库。
- 本机数据库在没有 FileVault 时，物理上可以读取。建议开启 FileVault。

## 6. 存储

- **全部存在本机**：`~/Library/Application Support/DeepThink/`，一台 Mac 一个 SQLite 数据库（WAL 模式）。
- 沿用 v0.1 的事件模型：`Event(ts_utc_ms, source, kind, dedupe_key, payload)`，追加写入，`dedupe_key` 唯一。
- 数据库里**没有图片**，只有文字和事件。
- 原始屏幕文字的保留期另定（见开放问题）；AI 生成的摘要长期保留。
- 不做云同步。以后需要多设备时，再考虑只同步加密的摘要。

## 7. 数据如何交给 AI

存储和处理分开：**数据长期留在本机；只在分析时，把脱敏后的片段发给 AI。**

```
屏幕文字 / 截图识别 / Chrome 历史 / 节奏信号
              │
              ▼
     脱敏（存储前）──► 本机 SQLite
                           │
              ┌────────────┘
              ▼
  ① 规则合并：同一 App、同一网站、同一项目连成片段
              │
              ▼
  ② 片段摘要：便宜的模型，可以是本地模型
              │
              ▼
  ③ 一天的理解：最强的模型只看摘要，还原任务、行为、跑神链条
```

- 发给云端之前**再脱敏一次**，并精简内容。
- 云端使用不保留数据、不用于训练的 API。
- 用户可以选择全部使用本地模型（效果较差，但数据不出电脑）。
- 用户纠正一次判断（比如"这段是查资料，不是跑神"），系统就记成个人规则，下次不再问 AI。

## 8. 权限

| 权限 | 用途 | 拒绝之后 |
| --- | --- | --- |
| 辅助功能 | 读屏幕文字（主力） | 只剩 App 切换、Chrome 历史和节奏信号，理解能力大幅下降 |
| 屏幕录制 | 截图识别兜底 | 读不到文字的 App 无法理解，其余照常 |
| 通知 | 每日复盘提醒 | 没有提醒 |
| 登录项 | 开机自动启动 | 需要手动启动 |

Chrome 历史通常不需要完全磁盘访问，待真机验证。

辅助功能和屏幕录制必须授权给签名过的 `.app`，不能授权给终端或脚本解释器。

## 9. 资源要求

- 空闲时（没有窗口或内容变化）接近零 CPU。
- 截图识别只在兜底时触发，且画面没变就不重复。
- 具体数字（CPU、内存、每天的磁盘增长）由 M0 和 M1 实测，不预先承诺。

## 12. 验证状态

本 PRD 中所有依赖真机的行为**都还没在这台 Mac 上验证过**，包括辅助功能的覆盖范围、Electron 和 Chrome 的开关效果、截图识别的速度、Chrome 历史的读取权限、资源占用。M0b 的目的就是验证这些。
