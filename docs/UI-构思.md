# Think My Day · UI 构思（草案 v1）

**日期：** 2026-10-30
**依据：** [PRD v0.4](PRD.md)、[CONTEXT.md](../CONTEXT.md) 的术语，以及 Jonas 2026-10-30 的口述：

1. 核心能力是「开启一天」，它是一天记录的开始。
2. 主界面有一个待办区和一个类似 Agent 的聊天区。
3. 菜单栏可以查看当天的所有记录。
4. 主界面要让用户一直知道当前的记录状态。

本文只讲结构和交互，不定颜色和字体。视觉风格等 Jonas 提供参考 App 之后再定。确认后，结论并入 PRD §9。

## 1. 设计原则

| 原则 | 在本产品里的含义 |
| --- | --- |
| 一屏一件主事 | 没开启时，界面上最显眼的只有「开启一天」；开启后，主角是聊天，待办是辅助 |
| 状态一直可见 | 记录中、未开启、已结束、出问题，四种状态在菜单栏图标和主窗口顶部都看得到，不用点开才知道 |
| 用原生组件 | 菜单栏弹出面板、窗口工具栏、右侧检查器栏、系统通知、设置窗口，都是 macOS 自带的，用户不用重新学 |
| 安静 | 白天唯一的打断是新工作询问；其他时候界面不弹窗、不闪烁、不标红 |
| 事实和推断分开 | 记录（事实）、事情（AI 推断）、用户补充，三者在界面上看得出区别；AI 的每个结论都能展开到依据 |
| 可撤销，少确认 | 勾待办、删待办、加入待办都可以撤销；只有「删除某一天」这种不可逆操作才弹确认 |

## 2. 记录状态：整个 UI 的骨架

界面上几乎所有地方都随记录状态变化，所以先定状态。

| 状态 | 什么时候 | 菜单栏图标 | 主窗口顶部 |
| --- | --- | --- | --- |
| **未开启** | 今天还没点「开启一天」 | 空心圆 ○ | 「今天还没开启 · 比计划晚 1 小时 32 分」 |
| **记录中** | 开启之后、结束之前 | 实心圆 ●，旁边显示已记录时长（可在设置里关掉） | 「● 记录中 · 10:32 开启 · 已记录 6 小时」 |
| **已结束** | 点了「结束一天」 | 对勾 ✓ | 「已结束 · 10:32 – 23:10」 |
| **需要处理** | 辅助功能授权被撤销、模型连不上等 | 圆点加感叹号 | 顶部状态条变成一句话说明原因，带「去处理」按钮 |

「需要处理」叠加在前三种状态之上，比如「记录中，但模型连不上」。按 PRD §8.6，模型出问题时记录照常进行，所以状态条写明「记录正常，整理暂停」。

## 3. 界面清单

| 界面 | 作用 | 出现方式 |
| --- | --- | --- |
| 菜单栏图标 + 弹出面板 | 看状态、开启或结束一天、看今天的所有记录 | 常驻 |
| 主窗口 | 开启一天、聊天复盘、待办 | 从菜单栏打开，或在 Dock 里点开 |
| 新工作询问 | 问是否加入待办 | 系统通知 |
| 设置窗口 | 模型、计划开始时刻、不看名单、保留期等 | ⌘, |
| 首次启动引导 | 授权、计划开始时刻、模型、不看名单 | 只出现一次 |

## 4. 主窗口

### 4.1 布局

```
┌───────────────────────────────────────────────────────────────────────────┐
│ ● ● ●   [● 记录中 · 10:32 开启 · 6 小时 ▾]     ‹ 10月30日 周四 ›     [历史] [▮]│  ← 工具栏
├───────────────────────────────────────────────┬───────────────────────────┤
│                                               │ 待办                3 项   │
│  AI：今天 10:32 开启，比计划晚 1 小时 32 分。   │ ☐ 交稳定币储备报告          │
│      主要事情：                                │   已进行 3 天               │
│      · 写稳定币研究文档   2 小时 3 分           │ ☐ 回复 Pluso 的 PRD 意见    │
│      · 排查 M0b 探测程序  1 小时 10 分          │   今天 · AI 问过后加入       │
│      ……                                       │ ☐ 整理 L2 项目笔记          │
│      › 展开依据                                │   已进行 6 天               │
│                                               │ ＋ 新增待办                 │
│  AI：有两件事想问你……                          │                           │
│                                  我：中午去吃饭 │ 今天勾掉                    │
│                                               │ ☑ 修 M0b OCR 卡住           │
├───────────────────────────────────────────────┤                           │
│ [ 回答、补充，或者问「这周我在 X 上花了多久」 ↑] │                           │
└───────────────────────────────────────────────┴───────────────────────────┘
        聊天区（可伸缩，主角）                         待办区（固定宽度，可收起）
```

- **工具栏左侧：记录状态按钮。** 一直显示当前状态（见 §2）。点开是一个小弹出面板：开启时间、和计划开始时刻的对照、今天的不看名单（可以改）、「结束一天」按钮。这样「让用户知道记录状态」和「结束一天」都放在同一个地方。
- **工具栏中间：日期切换。** 默认今天，‹ › 前后翻；点日期本身弹出日历。回看过去某天时，状态按钮换成「已结束 · 那天的起止时间」。
- **工具栏右侧：** 「历史」打开过往历史列表（§4.5）；最右边的按钮收起或展开待办区，和 Xcode、备忘录右侧检查器的用法一样。
- **聊天区在左，待办区在右。** 待办区固定约 300pt 宽，窗口变窄时自动收起成按钮。

### 4.2 主窗口随状态变化

| 状态 | 聊天区显示 | 待办区 |
| --- | --- | --- |
| 未开启（今天） | **开启一天面板**（§4.3），占据聊天区中央；不能聊天 | 正常显示，可以增删 |
| 记录中 | 和 AI 对话；AI 的开场白在第一次打开时生成，之后保留 | 正常 |
| 已结束 | 照常对话，可以继续复盘 | 正常 |
| 回看过去某天 | 那天的对话线程，可以接着聊 | 显示那天结束时的待办状态，只读 |

「开启一天」放在主窗口里，而不是单独弹一个窗口。原因是它是一天的第一个动作：每天早上打开主窗口，看到的就是它；点完之后，同一块区域直接变成聊天区。

### 4.3 开启一天面板（聊天区的「未开启」状态）

```
               ┌──────────────────────────────────────┐
               │  10月30日 周四 · 现在 10:32            │
               │  开启今天                             │
               │  计划 09:00 开始，晚了 1 小时 32 分     │
               │                                      │
               │  待办（没做完的已带过来，右侧可改）       │
               │  · 交稳定币储备报告        第 3 天      │
               │  · 回复 Pluso 的 PRD 意见  第 2 天      │
               │  [ 今天还想做什么？回车添加          ]   │
               │                                      │
               │  今天不看   1Password ×  MetaMask ×  ＋ │
               │                                      │
               │          [     开启一天！     ]         │
               └──────────────────────────────────────┘
```

- 什么都不填，也能直接点「开启一天！」。
- 和计划开始时刻的对照用中性语气，只陈述，不评价。
- 点了之后，面板退场，AI 的第一条消息出现：「已开启，比计划晚 1 小时 32 分。今天的待办有 3 项。」白天这个对话框也可以用，比如问「上午我都干了什么」。

### 4.4 聊天区里的几种消息

| 类型 | 样子 | 例子 |
| --- | --- | --- |
| AI 消息 | 左侧，无气泡，正文样式 | 开场白、观察和提问、建议 |
| 用户消息 | 右侧气泡 | 「中午去吃饭了」 |
| 依据 | AI 消息下方的「› 展开依据」，展开后是那段时间的原始记录列表 | 「11:02 焦点切到 Chrome · x.com」 |
| 系统确认 | 一行小字，前面一个对勾 | 「已把 12:05–13:10 记为『吃午饭』（你补充的）」 |
| 操作卡片 | AI 消息里嵌的按钮 | 「加入待办 / 不用」 |

### 4.5 过往历史

工具栏「历史」打开一个列表（也可以做成侧边栏），每行一天：日期、开启和结束时间、主要事情的前两项、勾掉了几个待办。右键或滑动可以「删除这一天」，删除前确认，并让用户选择是否连同事情和对话一起删（PRD §10）。

## 5. 菜单栏

菜单栏是「随时瞄一眼」的地方，满足 Jonas 说的「查看当天的所有记录」。

```
                                   ┌────────────────────────────────────┐
                        ● 6:00 ──▶ │ ● 记录中 · 10:32 开启 · 6 小时        │
                                   │ [ 结束一天 ]          [ 打开主窗口 ] │
                                   ├────────────────────────────────────┤
                                   │ 今天的记录                           │
                                   │ 10:32  写稳定币研究文档     68 分  ›  │
                                   │ 11:40  刷 X                25 分  ›  │
                                   │ 12:05  空白（待补充）       65 分  ›  │
                                   │ 13:10  排查 M0b 探测程序    70 分  ›  │
                                   │ 14:20  看 L2 项目资料       50 分  ›  │
                                   │ 15:10  微信聊天             25 分  ›  │
                                   │ 15:35  写稳定币研究文档（进行中）   ›  │
                                   │                     上次整理 16:15  │
                                   ├────────────────────────────────────┤
                                   │ 待办 3 项      ☐ 交稳定币储备报告 …   │
                                   └────────────────────────────────────┘
```

- **今天的记录**按时间列出今天的事情。点某一行，在同一个弹出面板里展开那段时间的原始记录：每次窗口切换、App、窗口标题、页面网址、读取方式（辅助功能或 OCR）。这就是「当天所有记录」的入口，不用打开主窗口。
- 列表底部注明「上次整理 16:15」。整理之后发生的事还没归纳成事情，以「整理后的原始记录」一段显示在最下面，保证用户看到的是**全部**记录，而不只是 AI 整理过的部分。
- **未开启时**，弹出面板只有一块：「今天还没开启 · 比计划晚 X」和「开启一天」按钮。点按钮打开主窗口的开启面板，不在菜单栏里填待办，免得两处重复。
- **已结束时**，顶部显示「已结束 · 10:32–23:10」，按钮变成「打开主窗口」。
- 待办在菜单栏里只做「看一眼、顺手勾」，最多显示 3 项，其余的点「打开主窗口」处理。

## 6. 新工作询问

- macOS 系统通知：「发现新工作：排查 M0b 探测程序 · 已持续 14 分钟 · 加入待办吗？」按钮是「加入 / 不用」。
- 点「加入」之后，待办区和菜单栏立刻出现这一项，带「AI 问过后加入」的标记；不理会就当不加。
- 频率上限、专注模式下不弹等规则见 PRD §8.2。

## 7. 设置窗口

标准的 macOS 设置窗口，分 4 页：

| 页 | 内容 |
| --- | --- |
| 通用 | 计划开始时刻、时区、开机启动、菜单栏是否显示已记录时长 |
| 记录 | 不看名单、OCR 开关、原始记录保留期（7 天 / 30 天 / 永不） |
| AI | 整理模型、对话模型、接入方式（官方 API / 兼容接口）、密钥、整理间隔、magpie 的说明 |
| 通知 | 新工作询问的持续时长门槛、频率上限 |

## 8. 首次启动引导

单独一个窗口，一步一页，每页只做一件事：

1. 欢迎：一句话说明 Think My Day 做什么、数据存在本机。
2. 授权：辅助功能（必须）、屏幕录制（OCR）、Chrome 自动化，各自一句话说明用途，旁边显示是否已授权。
3. 你的一天一般从几点开始？
4. 配置模型（可以跳过）。
5. 确认不看名单。
6. 结束引导，直接进入主窗口的开启一天面板。

### 9.15 空状态与异常

| 情况 | 显示 |
