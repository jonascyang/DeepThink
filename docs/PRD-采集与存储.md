## 1. 一句话

Think My Day 是 Jonas 个人用的 macOS 菜单栏 App：在用户选择的应用范围内记录窗口文字和活动经过，像会议纪要一样还原一天的时间、行为、App、内容与文档，并在这些记录之上，根据具体内容分析任务关系与可能的跑偏。原始记录存本机，发给外部模型或服务的内容由用户控制，并且常驻可见。

## 2. 背景与问题

Jonas 是加密研究员，并行使用多个 AI Agent、浏览器研究、聊天工具和文档。一天结束时，他不清楚时间去了哪里、什么时候被打断或跑偏。只记「哪个 App 开了多久」无法回答「当时在做什么任务」，也看不出 ADHD 式的碎片化切换。

只靠 Agent 日志和 Chrome History（v0.1 方案）覆盖面太窄：写文档、读网页、聊天、终端里的工作都看不到。所以采用屏幕文字作为主信号，全部本地存储、可控外发。v0.3 进一步明确：先保留能查证的活动记录，再根据具体内容整理任务和推断跑偏。多次切换可能是在同一项研究中交叉查证，打开某个 App 或网站本身不能说明偏离任务。

## 3. 目标与非目标

### 目标（v1）

1. 先记录每一段时间观察到的行为、涉及的 App、窗口、内容、页面或文档，形成可回看的每日纪要。
2. 记录同一时段同时可见的多个窗口及操作焦点，保留窗口之间的位置关系，避免把并排工作的情境压缩成一个 App。
3. 依据具体内容、前后文及可获得的任务背景，整理任务并分析是否跑偏；事实与推断分开，依据不足时明确无法判断。**v1 只还原和解释发生经过，不评价、不给建议、不打分。**
4. 全部原始数据在本机，库加密；写入前脱敏。
5. 外发给云端模型的内容由用户控制，复盘页常驻显示「今天发过什么」。
6. 无需 Apple 开发者账号即可稳定安装，重装后授权尽量保留。

### 非目标（v1）

- 周期性全屏截图与录屏；击键监听；剪贴板监听。
- 跨设备同步、iCloud、账号体系；iPhone。
- Mac App Store 分发。
- 自带或自训练模型（本机小模型仅用系统自带的，且可选）。
- 解密 ChatGPT Mac 缓存；把 Claude Desktop / Muse 等当作有完整日志的一等数据源。

## 4. 用户与场景

| 场景 | 用户要做什么 | 系统提供 |
| --- | --- | --- |
| 晚间复盘 | 像看会议纪要一样回看一天 | 按时间排列的活动记录、内容摘录与相关文档；任务归纳另列 |
| 多窗口工作 | 同时看网页、文档和 Agent | 同一时间段列出各窗口、位置、内容和操作焦点 |
| 找跑偏 | 了解什么时候转去了与原任务无关的内容 | 基于内容及前后任务关系的判断，附依据；不以 App 名称或切换次数直接定性 |
| 控制外发 | 想确认发了什么、发给谁 | 发送前预览；复盘页常驻展示外发内容、接收方和发送次数 |
| 控制监控范围 | 决定哪些 App 可以读内容 | 选择完整监控后读取窗口文字，含普通输入框；可改为只记标题或排除 |
| 重装升级 | 新版本不想重新授权 | 固定签名 + 授权保留检查 |

### 4.1 每日纪要的记录结构

每个活动段落至少包含下列信息；没有采集到的字段显示缺失及原因，不补写成事实。

| 字段 | 呈现要求 |
| --- | --- |
| 时间 | 开始与结束时间；采样中断或缺口单独标记 |
| 行为 | 记录实际观察到的动作，如窗口切换、页面显示、文字变化；「阅读」「撰写」等推断与直接记录区分 |
| App 与窗口 | App 名称、窗口标识和标题；同一 App 的两个窗口分开记录 |
| 内容 | 可回看的脱敏文字摘录，保留来源窗口、采集时间和读取方式；内容摘要能追溯到摘录 |
| 页面或文档 | 实际获取到的页面标题、URL、文档名称或路径；取不到路径时只列已知名称 |
| 桌面布局 | 同时可见的窗口、所在屏幕及位置关系、哪个窗口具有操作焦点；部分遮挡或内容不可读时标明 |
| 任务归纳与跑偏分析 | 与事实记录分开显示，关联依据片段；内容不足或含义不确定时标明，不强行归类 |

同一时间段有两个窗口并排时，纪要在同一段内分别说明两个窗口。具有操作焦点的窗口记为「正在操作」，其他窗口记为「同时可见」；可见不能证明用户已经阅读，也不能把两扇窗口的可见时长相加为工作时长。

### 4.2 示例（格式示意，非真实采集结果）

> **14:00—14:20**
>
> **正在操作：** 右侧文档窗口，标题《稳定币储备研究》；记录到正文文字变化。
>
> **同时可见：** 左侧 Chrome 窗口，显示某发行方储备报告页面；页面标题、URL 和可读取的内容摘录关联在本段。
>
> **任务归纳（推断）：** 编辑研究文档，并参考储备报告；依据为两个窗口的内容及先后变化。
>
> **跑偏分析：** 当前记录未发现明确的无关主题；两个窗口并排本身不作为跑偏依据。

## 5. 采集方案

### 5.1 信号分层

| 层 | 信号 | 用途 | 说明 |
| --- | --- | --- | --- |
| 主 | 窗口可见文字 | 形成客观记录，支持内容理解 | 按 App 授权读取，包含普通输入框文字；辅助功能读不到时，仅在用户开启 OCR 后对单个窗口本机识别 |
| 主 | 同时可见的窗口及布局 | 还原并排或多窗口工作的情境 | 记录各窗口标识、App、标题、屏幕、位置、可见状态与操作焦点；各窗口内容独立关联 |
| 辅 | 焦点切换、窗口标题 | 排列活动顺序与切换路径 | App 激活事件配合窗口焦点与标题变化；切换频率不单独用于判定跑偏 |
| 辅 | 焦点输入框字数增减 | 补充文字变化线索 | 从获准读取的普通输入框派生；不监听键盘，不把字数变化直接等同于写作成果 |
| 主 | 网页 URL / 标题 | 浏览研究归类 | Chrome 通过自动化（AppleScript）分别获取获准采集的可见窗口中选中标签的 URL 与标题；正文读取方式由 M0b 实测 |
| 辅 | Chrome 历史库 | 补充页面访问与跳转来源 | 读 Chrome 自己的 History 数据库（先复制再读，多 Profile），取访问时间与跳转来源；与窗口记录对照，不单凭历史库推断停留时长或跑偏 |
| 辅 | 无输入、睡眠 / 唤醒 / 锁屏 | 标记状态与记录缺口 | 无输入阈值默认 3 分钟（可选 1/3/5）；无输入不直接写成离开，可能仍在阅读或思考 |
| 辅 | Claude Code / Codex 会话 | 补充任务主题 | 只存会话主题等瘦字段，**不当主依据** |

### 5.2 按 App 决定监控范围

用户选择「完整监控」某个 App，即允许读取该 App 可见窗口中可读取的全部文字，包含正在编辑的普通输入框。无需另设「输入框只计字数」的内容限制；字数增减只是从已获准读取的内容中派生的辅助信息。此授权不代表应用提供了全部文字，也不代表读取未打开的文件或后台隐藏页面。

| 档位 | 行为 | 选择规则 |
| --- | --- | --- |
| 完整监控 | 读取可见窗口文字，含普通输入框；写入前脱敏 | 用户明确选择监控的 App；浏览器、文档、编辑器、终端、Agent、聊天和邮件均遵守同一规则 |
| 只记标题 | 只记窗口标题，不读正文或输入框 | 用户希望保留时间线但限制内容读取时选择；不因 App 属于聊天或邮件就强制降档 |
| 完全排除 | 不采集内容或标题，只留「被排除」的时间占位 | 密码管理器、钱包、银行默认排除；其他 App 可由用户排除 |

未选择的 App 不自动开启完整监控。App 的监控范围与外发权限分别控制：允许本机读取不等于允许发送给外部模型或服务。

密码输入框（AXSecureTextField）任何档位都不读。无痕窗口不采详细内容。

浏览器里的敏感页面不属于独立 App，三档策略管不到，单独处理：钱包插件页面（如 MetaMask，`chrome-extension://` 下）和密码管理器插件页面，按「完全排除」处理。

### 5.3 采样策略（待 M0b 实测定参数）

- 事件触发为主：焦点变化、标题变化、输入框字数变化；静止时低频采样（初始 5 秒，M0b 后调整）。
- 文字入库做去重与差分，同一屏不重复存。
- 同时可见的多个窗口按各自 App 策略采集，记录焦点窗口与参考窗口；切换焦点后更新关系。同一 App 的不同窗口保持独立标识。
- 读不到文字（Electron、自绘界面等）：先尝试开启 `AXManualAccessibility`；仍读不到时，由用户选择是否启用单窗口 OCR。OCR 总开关及每个 App 的开关默认关闭，开启后仍受 App 策略和敏感页面排除约束；限频（初始每个窗口每 30 秒最多一次，并限制整体频率），图片识别后立即丢弃。
- OCR 关闭、权限不足、窗口不可读或采样失败时，保留可用的标题与状态，并记录内容缺口；不据此生成完整活动描述。

### 5.4 多窗口采集边界

- 范围为当前活动桌面实际可见的窗口，包括同一 App 或不同 App 的多个窗口；不主动切换其他桌面，不遍历最小化或完全遮挡的窗口内容。
- 记录窗口所在屏幕与位置关系，支持说明「左侧网页、右侧文档」或「主屏文档、副屏参考资料」；布局变化记录时间。
- 读取范围按窗口可见区域约束；无法确认某段文字是否可见时标明读取范围不确定，不声称用户看过。OCR 只识别允许采集的窗口可见区域。
- 同时可见的窗口分别应用监控策略；其中一个被排除时，其他窗口照常记录，排除窗口只留占位，不泄露标题或内容。

## 6. 存储、加密与保留

| 项 | 要求 |
| --- | --- |
| 库 | 本机单库 SQLite（WAL），事件追加 + 游标，崩溃可重放 |
| 记录关联 | 保留时间、App、窗口标识、布局、操作焦点、内容摘录及读取状态；摘要和推断关联来源记录，缺口可追踪 |
| 加密 | **库加密，密钥存钥匙串**；无密钥无法读库 |
| 保留 | 原始屏幕文字默认 **30 天**后清理；复盘摘要、统计可更久，保留期可在设置修改 |
| 脱敏 | 写入前：API key、私钥、助记词（BIP39 ≥12 词）、JWT、信用卡号（Luhn 校验）、URL query 一律替换或丢弃；钱包地址是公开信息，保留 |
| 备份 / 导出 | `VACUUM INTO` 一致性快照；按日期导出 |

## 7. 每日纪要、内容分析与模型接入

### 7.1 分工

- **本地记录层（无网络）**：按时间整理观察到的窗口、内容、布局、文字变化、切换和记录缺口，提供 §4.1 的事实字段；没有模型时仍能回看这些记录。
- **模型分析层**：根据具体内容及前后文归纳任务、串联跨 App 活动，并分析可能的跑偏。接收脱敏后的选定记录或摘要，输出与来源关联；不把模型生成的描述写回为原始事实。
- **复盘原则（v1）**：每日纪要先呈现事实，任务归纳和跑偏分析另列；使用中性描述，不评价、不给建议、不打分。不把「文档文字变化」直接写成「报告已完成」，不把「聊天窗口出现一条文字」直接写成「消息已发送」。
- **本机小模型**：只使用 Mac 系统提供的模型，作为可选的片段摘要方式；没有它时，可把选定记录经预览后交给外部模型处理。任务理解与跑偏分析在模型未接入时标为不可用，不承诺仅靠本地统计完成内容理解。

### 7.2 跑偏判断依据

- 主要依据是具体内容与原任务的关系，包括页面正文、文档文字、Agent 对话及前后任务上下文。任务背景可由前后记录推断；用户若提供当前目标，可作为补充，不要求每次开工都填写。
- 同一主题下在网页、Agent 和文档间频繁切换，可能是正常查证；切换次数、App 名称、网站类别、输入量和停留时长均不能单独决定是否跑偏。
- 内容转向不同主题时，先记录主题变化；结合任务关系说明为何判断为可能跑偏。若原任务不明、记录缺失或无法判断相关性，输出「无法判断」，不强制下结论。
- 每条跑偏分析附相关时间、内容片段、任务关系和不确定之处；允许出现「内容相关，未发现明确偏离」的结论。统计数据可展示，切换频率不设用于定性跑偏或碎片化的固定阈值。

### 7.3 处理流程与接入方式（待定）

1. 本机采集并脱敏，保留来源、布局、时间及读取状态。
2. 本地去重和按时间分段，组织内容片段；这一步不依赖模型，不声称已经完成语义摘要。
3. 用户预览并选择可发送的记录。需要压缩内容时，由选定模型分段生成摘要，再用于整日整理；首次发送的原始片段也计入外发记录，不能隐去。
4. 将选定记录或摘要交给模型，输出每日纪要中的内容整理、任务归纳和跑偏分析，并关联输入依据。分段摘要继续保留来源标识。

接入方式尚未决定：可以直接调用相关 LLM 的 API，也可以连接其他模型服务或工具，例如 Grok Bot。Grok Bot 在此只是候选接入对象，具体产品、接口、权限与数据保留方式均未确定，不将其列为已接通或必选依赖。

通过可替换的 `ReviewProvider` 接口隔离接入差异；提供方、模型、密钥、可发送内容与结果格式在接入方案确定后补充。API 密钥存钥匙串；本期不依赖自建托管后端，也不预设必须采用 OpenAI 兼容或 Anthropic 接口。本轮不进行接入测试或真实模型调用。

### 7.4 外发控制

- 默认不外发，用户开启后才调用外部模型或服务；App 完整监控授权不自动开启外发。
- 发送前预览实际将发送的内容和接收方；可按 App、按时间段排除，包含为了生成摘要而发送的片段。
- 复盘页**常驻显示今天已发送的内容**、接收方、发送时间与次数；直接 API 和其他服务接入遵守同一要求。外发结果关联对应的发送记录，失败或重试状态可见。

### 7.5 复盘页术语

每日纪要、记录、时间线、内容摘录、正在操作、同时可见、任务归纳、可能跑偏、无法判断、无输入、记录缺口。界面区分事实与推断；v1 不出现建议或评分。具体界面文案在实现时补充。

## 8. 功能需求

| 编号 | 优先级 | 需求 | 验收要点 |
| --- | --- | --- | --- |
| FR-01 | P0 | App 与窗口焦点、标题 | 区分 App 激活与同一 App 内的窗口切换；边沿延迟目标 ≤1s（真机待验） |
| FR-02 | P0 | 辅助功能读窗口文字 | 完整监控含普通输入框；密码框不读；读取不到时记录缺口，不伪造内容 |
| FR-03 | P0 | 读不到时单窗口 OCR 兜底 | **由用户选择**：总开关 + 每个 App 单独开关，默认关闭；限频；图片不落盘 |
| FR-04 | P0 | 焦点输入框字数增减 | 按 App 授权从读取内容派生；标题档和排除档不读输入框；不监听键盘 |
| FR-05 | P0 | Chrome URL / 标题 / 跳转来源 | 多窗口时分别关联页面来源；History 库先复制再读，不单独推算活动时长；无痕不采详细内容 |
| FR-06 | P0 | 无输入、睡眠、锁屏边沿 | 无输入阈值默认 3 分钟，不自动写成离开；锁屏后停止内容读取，唤醒后重新确认窗口状态 |
| FR-07 | P0 | 三档 App 策略与设置 | 选择完整监控即允许读取普通输入框；只记标题与排除仍可选；本机监控与外发分别控制 |
| FR-08 | P0 | 采集时脱敏 | 红队用例：db 与 WAL 字节中无明文密钥 |
| FR-09 | P0 | 库加密 + 钥匙串密钥 | 删除密钥后库不可读；30 天清理生效 |
| FR-10 | P0 | 本地事实记录与时间线 | 无网络可查看时间、窗口、内容摘录与缺口；推断和事实分开，字段见 §4.1 |
| FR-11 | P1 | 模型内容整理与复盘 | 基于具体内容归纳任务和分析跑偏，附来源与不确定性；接入方式待定；遵守外发预览和记录要求 |
| FR-12 | P1 | Claude/Codex 会话主题（辅助） | 只存主题；去重；不当主依据 |
| FR-13 | P1 | 健康与缺口提示 | 权限被撤、采集中断在复盘可见 |
| FR-14 | P2 | 本机小模型片段摘要 | 可选；不可用时静默降级 |
| FR-15 | P2 | 导出与备份 | 见 §6 |
| FR-16 | P0 | 多窗口与桌面布局记录 | 同 App / 不同 App 的并排窗口分别记录内容与位置；区分焦点和同时可见；排除窗口只留占位，同段时长不重复累加 |
| FR-17 | P0 | 每日纪要展示与依据回看 | 按 §4.1 呈现活动段落；可展开对应窗口、内容、页面或文档；任务归纳与跑偏分析可追溯到来源，缺失字段明确标注 |

以上为后续实现的验收要求，不代表已经通过验证。本轮范围见 §12。

## 9. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 技术栈 | 纯 Swift，实现菜单栏 App、采集、存储与复盘；不沿用 Python 摄入原型 |
| 资源 | 目标：平均 CPU 低（M0b 实测后定具体数字）；内存常驻小；OCR 限频 |
| 可靠性 | WAL；事件与游标同事务；schema 前向迁移 |
| 隐私 | 无击键、无剪贴板、无全屏截图；读取内容写入前脱敏；原始文字 30 天 |
| 网络 | 默认零网络；仅在用户开启外发后向其选择的模型或服务发送，记录所有摘要与复盘处理阶段的外发 |
| 打包 | 通用二进制（arm64 + x86_64）`.app`，`LSUIElement` 菜单栏，`SMAppService` 登录项 |

## 10. 隐私总览

| 记 | 不记 |
| --- | --- |
| 前台 App、切换时刻、窗口标题 | 键盘按键内容、鼠标轨迹、剪贴板 |
| 用户选择「完整监控」的 App 可见窗口文字，含普通输入框（脱敏、加密、30 天） | 排除档 App 的标题与内容；密码输入框；钱包与密码管理器插件页面 |
| 获准读取的输入框文字及其字数变化 | 标题档、排除档的输入框内容；未打开文件、隐藏页面的内容 |
| 同时可见窗口的布局、焦点与各自读取状态 | 将「同时可见」冒充「已阅读」的记录；被排除窗口的具体信息 |
| 读不到文字时的单窗口识别结果（由用户选择是否启用） | 截图图片（识别后丢弃）；全屏录屏 |
| Chrome 当前标签 URL（去 query）与标题；历史库里的访问时间与跳转来源 | 无痕窗口详细内容 |
| 无输入 / 睡眠 / 锁屏边沿 | 锁屏后窗口内容；仅凭无输入生成的「已离开」结论 |

完整监控允许读取聊天、邮件或编辑中的文字，范围由用户按 App 选择；密码框排除和写入前脱敏继续生效。残余风险是未覆盖的秘密形态，靠 App 策略、脱敏和外发预览降低；Accessibility 权限只授给签名的 `.app`。

## 11. 签名与安装

- 不走 Mac App Store、不要求 Apple 开发者账号：用一张固定自签证书给 `.app` 签名。
- 历史文档称已在云端验证同一证书重建时的代码身份（designated requirement）保持一致，当前仓库缺少可复核的实现与验证产物。授权在升级后保留仍属预期，需后续真机验证；本轮不执行。
- 代价：首次打开需右键 → 打开；无公证。**决定：不开通 Developer ID（Jonas 2026-10-29）。** 若真机验证授权不保留，则减少升级频次，升级后在 App 内引导重新授权，不走付费账号。
- 证书与私钥只放本地，**不提交 git**。
- 需要的授权：辅助功能（必须）、自动化 → Chrome（取 URL）、屏幕录制（仅 OCR 兜底，可选）、登录项。

## 14. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| Electron / 自绘界面读不到文字 | 任务判断变弱 | 尝试 `AXManualAccessibility`；仅在用户开启时使用单窗口 OCR，否则标明缺口；M0b 后续量化 |
| 自签证书授权不保留 | 每次升级要重新授权 | M0b 验证；减少升级频次，App 内引导重新授权（不开 Developer ID） |
| 读取内容含他人原话或编辑中文字 | 监控范围与理解不一致 | 按 App 明确完整监控范围，保留标题档与排除档；监控与外发分开控制 |
| 模型输出不稳或误判跑偏 | 复盘不可信 | 依据具体内容和任务关系，事实与推断分开，保留来源；不足时无法判断，无模型时保留客观记录 |
| 多窗口可见性或布局不完整 | 错认参考资料、重复计算时长 | 窗口分别标识，区分操作焦点与可见状态；缺口明确显示，同一时段不叠加为工作时长 |
| 外部服务接口或数据保留方式不清楚 | 接入受阻或无法说明外发范围 | 接入方案保持待定，确定前核对能力和数据流；所有外发阶段统一预览并记录 |
| macOS 更新改变辅助功能行为 | 读取失效 | 健康提示 + 探测版回归 |
| 电量与 CPU | 影响日常使用 | 事件驱动、限频、M0b 实测 |
